## 坑一：Tez 引擎部署失败

### 现象
YARN 容器启动时报错：

Could not find or load main class org.apache.tez.dag.app.DAGAppMaster

### 尝试的修复
- 添加 `tez.lib.uris.classpath` 配置
- 禁用 `tez.use.cluster.hadoop-libs`
- 修改 `yarn.application.classpath`
- 重新打包上传 HDFS，赋予 777 权限
- 重启集群、清理缓存

### 结论
Tez 0.10.2 与 Hadoop 3.1.3 存在 Classpath 加载冲突，权衡后放弃。

### 替代方案
改用 Hive MR 引擎参数调优 + 分区表设计，ETL 耗时从 90 分钟降到 45 分钟。

### 收获
- 深入理解了 YARN 的类路径加载机制
- 学会了分析 Container 日志定位问题
- 认识到组件版本兼容的重要性

## 坑二：YARN ResourceManager 不在 hadoop142 上

### 现象
`yarn node -list` 显示 ResourceManager 在 hadoop143。

### 原因
集群架构中，NameNode 在 hadoop142，ResourceManager 在 hadoop143。

### 解决
正常现象，提交作业时自动连接到 hadoop143。

yarn node -list

# 连接: hadoop143/192.168.107.143:8032

## 坑三：Phoenix JDBC 连接超时

### 现象

java.sql.SQLException: Connection refused

### 排查
1. ZooKeeper 是否启动：`jps | grep QuorumPeerMain`
2. 端口是否监听：`netstat -tlnp | grep 2181`

### 解决
启动 ZooKeeper：
```bash
/opt/module/zookeeper-3.5.7/bin/zkServer.sh start
```

## 坑四：Flume OOM（内存溢出）

### 现象

```
Exception: java.lang.OutOfMemoryError
Exception in thread "ReadOnlyZKClient..." java.lang.OutOfMemoryError: GC overhead limit exceeded
```

### 原因

Flume 默认 JVM 堆内存只有 20MB，Phoenix 驱动加载时内存不足。

### 解决

启动时指定堆内存：

bash

```
bin/flume-ng agent ... -Xmx1024m
```

## 坑五：DolphinScheduler 部署 - 数据库连接问题

### 现象

text

```
Connection to 127.0.0.1:5432 refused
The following 1 profile is active: "postgresql"
org.postgresql.util.PSQLException: Connection to 127.0.0.1:5432 refused
```

### 原因

DolphinScheduler 默认使用 PostgreSQL，需要改为 MySQL。

### 解决步骤

1. 修改 `conf/datasource.properties`：

properties

```
spring.datasource.driver-class-name=com.mysql.jdbc.Driver
spring.datasource.url=jdbc:mysql://hadoop142:3306/dolphinscheduler?useUnicode=true&characterEncoding=UTF-8&useSSL=false
spring.datasource.username=root
spring.datasource.password=123456
```



1. 修改各子服务的 `conf/application.yaml`，将 `spring.profiles.active` 从 `postgresql` 改为 `mysql`
2. 复制 MySQL 驱动到各子服务的 `libs/` 目录：

bash

```
cp lib/mysql-connector-java-5.1.37.jar master-server/libs/
cp lib/mysql-connector-java-5.1.37.jar api-server/libs/
cp lib/mysql-connector-java-5.1.37.jar worker-server/libs/
cp lib/mysql-connector-java-5.1.37.jar alert-server/libs/
```



1. 删除 PostgreSQL 驱动（避免干扰）：

bash

```
find . -name "*postgresql*.jar" -exec rm -f {} \;
```



1. 执行建表脚本：

bash

```
mysql -uroot -p123456 dolphinscheduler < tools/sql/sql/dolphinscheduler_mysql.sql
```

## 坑六：DolphinScheduler 端口 8080 被占用

### 现象

text

```
Failed to bind to /0.0.0.0:8080
java.net.BindException: 地址已在使用
```



### 解决

bash

```
# 查找占用 8080 的进程
sudo netstat -tlnp | grep 8080
# 杀掉进程
sudo kill -9 <PID>
```



### 根本解决

修改 `api-server/conf/application.yaml` 中的端口：

yaml

```
server:
  port: 12345
```

## 坑七：DolphinScheduler ZooKeeper 连接失败

### 现象

text

```
zookeeper connect timeout: localhost:2181
org.apache.dolphinscheduler.registry.api.RegistryException: zookeeper connect timeout: localhost:2181
```



### 原因

`application.yaml` 中 ZooKeeper 地址是 `localhost:2181`，但 ZK 在三台节点上。

### 解决

修改各子服务 `conf/application.yaml` 中的：

yaml

```
registry:
  type: zookeeper
  zookeeper:
    namespace: dolphinscheduler
    connect-string: hadoop142:2181,hadoop143:2181,hadoop144:2181
```

## 坑八：DolphinScheduler 服务启动后端口不监听

### 现象

进程存在但 `netstat` 看不到端口。

### 原因

服务启动失败，进程是残留的僵尸进程。

### 解决

```
# 清理所有进程
./bin/dolphinscheduler-daemon.sh stop master-server
./bin/dolphinscheduler-daemon.sh stop worker-server
./bin/dolphinscheduler-daemon.sh stop api-server

# 清理日志
rm -rf master-server/logs/* worker-server/logs/* api-server/logs/*

# 重新启动
./bin/dolphinscheduler-daemon.sh start master-server
./bin/dolphinscheduler-daemon.sh start worker-server
./bin/dolphinscheduler-daemon.sh start api-server
```
